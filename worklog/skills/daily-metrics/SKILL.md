# daily-metrics：今天做多少、花多少、划不划算

## 設定

安裝後把下面兩行換成實際值再存檔。這兩個值就住在這個檔案裡，因為沙盒的家目錄
每次對話重開就清空，`~/.claude/worklog.env` 存不住。

```
WORKLOG_URL  = https://script.google.com/macros/s/XXXX/exec
WORKLOG_TOKEN = 你的TOKEN
```

還是 `XXXX` 就停止，回覆「工作看板還沒填 URL 和 TOKEN」。

## 要抓的五個數字

| 參數 | 是什麼 | 去哪裡拿 |
|---|---|---|
| revenue | 今天到目前為止的營業額（含稅實收，不含未付款） | Shopline 後台 |
| orders | 今天的訂單數 | Shopline 後台 |
| spend | 今天的廣告花費 | FB 廣告管理員 |
| clicks | 今天的**連結點擊**（廣告帶進來的流量，不是全站流量） | FB 廣告管理員 |
| carts | 今天的**加入購物車**次數 | FB 廣告管理員 |

看板會自己換算三個比率，不用送：
ROAS＝revenue÷spend、流量成本＝spend÷clicks、加購成本＝spend÷carts。

`clicks` 用「連結點擊」而不是 GA4 的全站工作階段，是刻意的——這樣流量成本才是
「這筆廣告費買到一個訪客多少錢」。要改成看全站流量的話，成本那兩個數字就沒有意義了。

## 步驟

**一、Shopline。** 開後台的訂單或分析頁，日期篩今天，讀出營業額與訂單數。
取消與未付款的不算。抓不到就把 revenue 和 orders 留空，不要猜。

**二、FB 廣告。** 優先用 fb-ads-mcp 的洞察工具，帳號取「起士公爵2025」，
日期範圍 today，層級取帳號合計，欄位要 spend、連結點擊、加入購物車。
MCP 不通再退回瀏覽器開廣告管理員，日期選「今天」，看總計列。

**三、寫回看板。** 把抓到的數字組成網址，用瀏覽器開啟（沙盒的代理擋掉
`script.google.com`，`curl` 一定失敗，不要浪費時間重試）：

```
<WORKLOG_URL>?action=metrics_save&token=<WORKLOG_TOKEN>&revenue=<...>&orders=<...>&spend=<...>&clicks=<...>&carts=<...>
```

只送抓到的那幾個，沒抓到的參數整個不要放進網址——送空字串會被拒絕，
但漏送的欄位會保留上一次的值，不會被清掉。

數字送純阿拉伯數字就好，有千分位或錢字號也吃得下。
頁面出現 `{"ok":true,...}` 才算成功；失敗就重開一次同一個網址，第二次還失敗
就回覆「今日數據寫入失敗：<原因>」，不要再試第三次。

## 給使用者的回覆

一行講完，不要解釋流程：

```
今日 營業額 $48,200（31 筆）· 廣告 $12,500 · ROAS 3.86x · 流量 1,840（$6.79）· 加購 96（$130）
```

ROAS 掉到 1.5 以下就多補一句提醒；抓不到的欄位寫「—」，並說是哪一邊沒抓到。

## 排程

Cowork 排程任務，週一到週日每小時（建議 10:00–21:00），內容一句：
「執行 daily-metrics skill」。

同一天重複跑會覆蓋當天那一列，不會愈疊愈多。
