# 工作看板

個人每日／每週／每月工作看板。資料放在 Google Sheet，Claude Code 與 Cowork 做完的事自動寫進去，手機和桌面都能看、能排任務。

- 試算表：<https://docs.google.com/spreadsheets/d/136z3S0ADQHRda3q8O_B_GFBlBlBuE-oEg0mxIeT0FVc/edit>
- 後端＋介面：Apps Script（本資料夾的 `Code.gs`、`index.html`、`appsscript.json`）
- 自動記錄：`hooks/`（Claude Code）、`skills/work-log/`（Cowork）

## 安裝

最快的方式：把 `COWORK-SETUP.md` 的指令貼進 Cowork，它會在你的電腦上完成全部安裝。手動步驟見下方各節。

## 資料結構

「紀錄」一列一件事，「任務」一列一個待辦。日／週／月看板是從「紀錄」依時間範圍聚合出來的，不用另外維護。

| 工作表 | 欄位 |
|---|---|
| 紀錄 | id, 開始時間, 結束時間, 來源(Claude Code / Cowork / 手動), 專案, 標題, 狀態, 摘要, 產出連結, session_id, 任務id, 檔案位置 |
| 任務 | id, 建立時間, 標題, 專案, 到期日, 優先(A/B/C), 狀態(待辦/進行中/完成/取消), 下一步, 等待者, 預估時數, 備註, 完成時間, 執行者(我/AI/一起), 重複 |
| 簡報 | 日期, 產生時間, 內容（早晨簡報，一天一列） |
| 分區 | id, 名稱, 顏色, 順序（資料區的欄位，自己開的） |
| 資料 | id, 分區, 標題, 內容, 順序, 建立時間（資料區的卡片） |
| 指標 | 日期, 營業額, 訂單數, 廣告花費, 流量, 加入購物車, 更新時間（一天一列，Cowork 寫） |
| 設定 | TOKEN |

## 部署（做一次）

1. 開試算表 → 擴充功能 → Apps Script。
2. 把 `Code.gs` 內容貼進預設的 `程式碼.gs`；新增「HTML」檔命名 `index`，貼上 `index.html`。
   專案設定 → 勾「在編輯器中顯示 appsscript.json」，把 `appsscript.json` 貼上（時區與存取設定）。
   （在 Cowork 也可以用 `gas-inject-and-run` skill 注入。）
3. 在編輯器選 `setup` 執行一次，授權。執行紀錄會印出 `TOKEN`，「設定」工作表也會有。
4. 部署 → 新增部署作業 → 類型「網頁應用程式」→ 執行身分「我」、存取權「所有人」→ 部署。複製 `/exec` 網址。
5. 手機瀏覽器開 `/exec` 網址，貼一次 TOKEN，加到主畫面。

存取權設「所有人」是為了讓 curl（Claude Code hook）能打得進來；網頁與 API 都靠 TOKEN 擋。TOKEN 外洩就到 Apps Script「專案設定 → 指令碼屬性」改 `TOKEN`，重跑 `setup`，手機重新貼一次。

## 各頁在做什麼

| 頁面 | 內容 |
|---|---|
| 每日看板 | 三欄：AI 正執行、今日、明日。在哪一欄按「＋ 新增任務」，日期就跟著那一欄；正執行欄新增的直接標進行中 |
| 看板總覽 | 任務排在哪一天、做完了沒。週看七格、月看月曆格，**週檢視可以把任務拖到別天**（＝改到期日）|

| AI 工作時間表 | 日曆式的日／週／月，可往前往後翻。**只畫實際跑過的紀錄**（Claude Code 與 Cowork），任務不進這頁 |
| AI 專案池 | **只收交給 AI 的事**（執行者是 AI 或一起）：建議順序、昨天實際執行的紀錄（Cowork 與 Claude Code 各一欄）、還剩什麼（依 A/B/C 並排三欄）|
| 資料庫 | Claude Code、Cowork、手動做出來的東西的網址，可依來源過濾。不列在側邊欄，從「設定」進去 |
| 資料區 | 自己開欄位、自己放卡片的看板，存日常會回頭查的東西。標題點一下就能改，卡片可拖到別欄 |
| 完成項目 | 那段期間實際做完了什麼，附產出連結（可點）與檔案位置（點一下複製）。可切本週／本月／全部 |
| 設定 | 試算表連結、TOKEN、自動記錄的來源 |

昨天沒做完的任務今天照樣出現在「今日工作」，但**到期日不會被改寫**——改掉就再也看不出這件本來哪天該交。卡片改標「順延 N 天 · 需完成 9/3」，拖了幾天跟原訂期限一眼看得到。

「昨天執行的內容」分成 Cowork 與 Claude Code 兩欄，一眼看得出昨天是誰在做事、誰整天沒動靜。
Claude Code 那欄空的時候會寫明原因——hook 得裝在自己的電腦上，跑在雲端的 session 送不出來。
其他來源（手動補的）只有在真的有紀錄時才多長一欄出來。

「還剩什麼」依 A/B/C 分三塊而不是依專案：決定「現在做哪一件」時看的是輕重，不是它屬於誰，
專案名稱本來就印在每張卡片上。A 級掛零會直接寫出來，那通常代表今天沒有真正推進結果的工作。
三塊是左右並排的三欄（跟每日看板同一種網格），上下堆疊的話一次只看得到 A，B 和 C 要捲很久才看到。

建議順序的排法：逾期最急（越久越前面），已經開工的往前拉，再看 A/B/C；卡在別人身上（有等待者）的往後排，因為自己動不了。

## 看板總覽與 AI 工作時間表的差別

兩頁吃同一個 `projects` API，但各管一半，不重複：**看板總覽**只畫任務（排在哪一天、做完了沒），
**AI 工作時間表**只畫紀錄（Claude Code 與 Cowork 真的跑了什麼、跑了多久）。
前者回答「這週該做的排開來長怎樣」，後者回答「時間實際花去哪了」。

時間表原本在時間軸上方多一列「全天」放當天到期的任務，計畫與實際疊在同一張圖上。
任務一多（例如從 Notion 匯進十幾筆）那一列就被塞爆，而且跟看板總覽完全重複，所以拿掉了。
`monthCal()` 的任務層改成用參數關閉，看板總覽的月檢視不受影響。

## AI 工作時間表的日曆

參考 Google 日曆的排法。日與週是時間軸，依實際起訖時間鋪出「紀錄」——也就是 Claude Code 與 Cowork 真的跑了什麼、跑了多久。頂端四個數字：區間、幾筆幾小時、Claude Code 幾筆、Cowork 幾筆。

時間軸範圍預設 8 點到 19 點，會自動往外擴到蓋住當天最早與最晚的紀錄。同一時段重疊的紀錄並排不互蓋。還沒結束的紀錄畫成虛線框，今天那欄有一條紅色的現在時間線。

月是格子，每格標當天有幾筆紀錄。（同一個 `monthCal()` 在「看板總覽」是另一種模式，那邊每格顯示最多三件任務、其餘收成「還有 N 件」。）

## 統計列與早晨簡報

每日看板分成三段，每段前面有一條標題橫線（營運數字／早晨簡報／今天要做的），
不然三塊背景邊框都一樣會疊成一整面牆。營運數字的「幾點更新」放在它那條橫線的右邊。

三條橫幅：早晨簡報、營運數字、統計列。三顆開關並排在日期列，
不會有的在這裡、有的藏在 ▾ 選單裡。每一顆的開關都記在這台裝置。
統計列（已完成任務、優先任務占比、專注時間、本週進度）預設不顯示；
早晨簡報只有當天真的產生過才會出現那顆鈕。
（「目標追蹤」頁已改成「完成項目」，那邊列的是實際做完的東西，不再有這些統計。）

早晨簡報原本住在那條列子的最左格，統計列收起來後改放在日期列下面一行——不然
每天跑的 morning-brief 就沒地方顯示了。右邊的 ✕ 可以收起來，收起後從標題列的
「早晨簡報 ▾」叫回來，選擇記在這台裝置。

簡報是 morning-brief 寫的純文字，格式固定成「標籤：內容」四段（昨天／今天必做／
進行中／建議）。畫面上照這個格式拆成分段條列：標籤在左，內容在右，有編號的那幾段
再拆成 `<ol>`。編號只認一到兩位數後面接句點再接非數字，所以「迭代到第 9 版」、
「2026.09.04」、「轉換率 3.5%」不會被誤拆。認不出標籤的行會原樣接在上一段後面，
簡報寫成什麼樣子都不會掉字。

## 固定每週／每月要做的事

任務的「重複」欄位：不重複（預設）／每天／每週／每兩週／每月／每季／每年。
編輯視窗有下拉可選，卡片標題前面會標 🔁。

**做完的那一刻長出下一次**，原本那筆維持完成留在紀錄裡——不是把同一筆的日期往後推。
這樣「完成項目」看得到你每週都有做，而不是只剩一筆永遠做不完的東西。
按「完成 ✓」的提示會直接寫「已完成，下一次 9/14」。

下一次的日期是**從這次的到期日推**，不是從今天：每週一的事就算你週三才做完，
下一次還是下週一，不會愈飄愈後面。但如果推出來的日子已經過了就繼續往後推，
免得一完成就馬上又逾期。加月份會夾住月底，1/31 加一個月是 2/28 不是 3/3。

防重複長兩筆：已經完成過的再按一次不會長；已經有一筆同名同專案的未完成任務也不長。

## 誰做：我 / AI / 一起

「碳標籤申報」和「Claude SEO 優化」從資料上長得一模一樣，系統猜不出哪件該交給 AI，
所以這是一個欄位（任務表的「執行者」），不是推論。試過從專案名或從有沒有 AI 紀錄去推，
兩個都會錯：行政裡有 AI 能做的（月報告），非行政裡也有得自己去談的（合約等 PN 回覆）。

**空白一律當「我」。** 新任務、匯進來的任務都不必回頭整理，只有真的要交出去的那幾件才改。
反過來預設 AI 的話每一筆都要動。「一起」是 AI 產初稿、自己收尾，算在 AI 那邊。

哪裡看得到：

- **每日看板**：全部都在（那是你的一天）。交給 AI 的卡片標題前面有 🤖，一起的是 🤝
- **AI 專案池**：只收 AI 與一起。空的時候會告訴你自己手上還有幾件，並指路怎麼丟出去
- **編輯視窗**：「誰做」三選一，預設我

Claude Code 或 Cowork 對某個任務寫了紀錄（`log` 帶 `task_id`），那件事的執行者會自動
補成 AI，不用手動維護。只在目前還標「我」時才改——已經標「一起」的是刻意的，不會被蓋掉；
手動紀錄也不算，那是自己做的。補標記失敗不會讓寫紀錄整個失敗，紀錄本身比較重要。

## 從 LINE 丟一句話進來

自己的 LINE 官方帳號傳一句話給它，就變成一件任務，出現在今日工作最下面，
它會回你「已加到今日工作：XXX」。第一行當標題、其餘放備註（貼一整段也不會撐爆卡片），
優先 B、執行者「我」、專案標成 `LINE`。

### 開頭可以寫日期

`明天 交報告`、`下週三 盤點`、`9/15 對帳`、`2026-12-25 尾牙場地`。認得的寫法：

- 今天／今日／明天／明日／後天／大後天
- 週三／周三／禮拜三／星期三（下一個那天，今天剛好是週三就算下週）、下週三（再加一週）
- `9/15`（已經過了的日期當明年——待辦寫日期指的都是還沒到的那一天）、`2026-12-25`

**日期只認開頭，而且後面要斷開**（空白或標點）。「明天要問的事」整句都是標題，
不會被吃掉前兩個字變成一件叫「要問的事」的任務——那種錯使用者不會發現。
沒寫日期就是今天，從 LINE 丟進來的多半是現在想到、今天要處理的事。

回話會講出實際排到哪一天（「已加到明日工作」「已排到 9/15」），
寫了「明天」卻回「已加到今日工作」的話，一眼就知道沒解析到。

### 身分怎麼驗

**不是用 LINE 的 X-Line-Signature。** Apps Script 的 `doPost` 讀不到 request header，
那個簽章根本拿不到，HMAC 在這個平台上做不出來。所以改成兩道：

1. webhook 網址上帶一段隨機字串（`?line=xxxx`），只有你和 LINE 知道
2. 只認自己的 userId（指令碼屬性 `LINE_USER`）

第一道擋掉亂打這個網址的人；第二道擋掉「網址外流」——外流了，別人傳進來也只是被無視。
**那段網址本身就是密碼**，不要貼給別人；真的外流就換一段、重設 webhook。
沒設 `LINE_SECRET` 的話整個入口是關的：預設開放等於把新增任務的權限送給任何知道網址的人。

### 設定（做一次）

1. [LINE Developers](https://developers.line.biz/) 建一個 Messaging API channel，
   拿到 **channel access token**（長期）。
2. Apps Script → 專案設定 → 指令碼屬性，加三個：

   | 屬性 | 值 |
   |---|---|
   | `LINE_SECRET` | 自己想一段夠長的隨機字串，例如 32 個英數字 |
   | `LINE_TOKEN` | 上一步的 channel access token |
   | `LINE_USER` | 先留空 |

3. 重新部署一次（新版本）。這次會多要一個「連線至外部服務」的權限——回話要打 LINE 的 API。
4. LINE Developers 的 Messaging API 頁把 Webhook URL 設成
   `https://script.google.com/macros/s/XXXX/exec?line=你的LINE_SECRET`，打開 Use webhook，
   並把「自動回覆訊息」關掉（不然官方帳號會用罐頭訊息回你）。
5. 加自己的官方帳號好友，傳一則訊息。它會回你的 `userId`，把那串貼進 `LINE_USER`。
   從這一刻起只有你傳的話會被記下來。

### 壞掉的時候

webhook 回非 200 會被 LINE 重送，同一句話就變成好幾張卡片，所以**任何錯誤都回 200**，
錯誤留在 Apps Script 的執行紀錄裡。沒設 `LINE_TOKEN` 時不會回話，但任務照記——
回不了話不該連記都不記。

## 從別的工具匯入

Notion 之類的工作項目搬進來，見 [NOTION-IMPORT.md](NOTION-IMPORT.md)。
重點只有一個：貼進「任務」工作表的列沒有 id，看板認不出那張卡片，
按「開始」「完成」都會失敗——所以貼完一定要到「設定 → 從別的工具匯入」
按一次「補齊匯入的任務」。那支同時會把 High／P0／Done 這些寫法換成
A/B/C 與待辦／進行中／完成，並把各種日期格式統一成 `yyyy-MM-dd`。
看不懂的日期不會亂猜，原文移到「備註」並清空到期日。

## 資料區

跟任務、紀錄不同性質——那兩個有時間軸，這個沒有，就是一疊你會回頭查的東西：連結、片段、參考。
所以獨立兩張表：「分區」是你自己開的欄位，「資料」是欄位裡的卡片。

卡片點下去會開一整頁，那一頁刻意長得像一份文件而不是一張表單：大標題（沒有「標題」那種
欄位名）、下面一排安靜的屬性（分區、建立時間）、一條分隔線，然後整片可以寫字的地方。
框線愈少愈像在寫東西而不是在填格子，所以關閉鈕退到角落當幽靈、底下那排也不再拉線
把文件切斷。⌘/Ctrl+Enter 存檔、Esc 關閉。原本是在卡片上長一個三行的 textarea，
寫長一點就看不到自己在打什麼。「＋ 新增」還是就地打字，快速記一筆不用開頁面。

沒有建立時間的舊卡片，那一組屬性整個藏起來——留一個「建立」配一片空白比不顯示更難看。

標題和內文現在是獨立的兩欄。舊資料的第一行就是標題（那時候標題是從內文推出來的），
所以卡片預覽只在「第一行剛好等於標題」時才把它去掉，新資料的第一行不會被亂砍。

全部就地編輯，不跳瀏覽器的輸入框：按「＋ 新增分區」直接在新欄位打名稱，按「＋ 新增」直接在
欄位裡打卡片內容，點卡片就地改。Enter 存檔、Shift+Enter 換行、Esc 取消、點別處也會存。

卡片的第一行是標題，其餘顯示在下面；整段只有一個網址就顯示成可點的連結。滑過卡片右上角有
刪除鈕（手機常駐），要再確認一次。

分區標題點一下直接改。刪分區時裡面的卡片不會跟著刪，會落到「未分類」那一欄——誤刪一整欄的
代價太大。卡片可以拖到別的分區。

## 完成項目

把兩個來源合在一起：狀態為完成的「任務」，以及 Claude Code / Cowork 送進來的「紀錄」。
紀錄如果掛在某個任務底下（`task_id`），就不重複列那個任務，以紀錄為準——它才有連結。

每一項顯示產出連結（可點開）與檔案位置（本機路徑點不開，做成點一下複製）。這兩欄由
`work-log` skill 在任務結束時寫入；沒填的話，那筆事後就只剩一行標題。

## 字級

標題列有 A− / A＋，每按一次加減一成，範圍 100%–260%，預設 200%。設定頁也有一組，
手機標題列擠的時候用那邊。設定存在這台裝置，手機和桌機可以各自設不同大小。

做法是所有字級都用 `rem`，縮放只改 `html` 的 `font-size`（`--z`）。跟文字綁在一起的
尺寸——頭像、圖示鈕、進度環、日期圓底、側欄寬度、日曆一小時的高度——也一起換算，
不然字放大會被容器切掉。`drag.test.js` 會檢查沒有漏掉的 px 字級。

## 卡片長相

卡片上不放專案與優先級的標籤，太佔空間。優先級改成左側一條色帶（A 紅、B 橘、C 藍，滑過去有提示），專案縮成「下一步」那行前面的小字。資訊都在，但一張卡從四行變三行。

## 編輯視窗

按下「儲存」的當下就關窗，不等伺服器回來。Apps Script 一趟要一兩秒，視窗停在那邊
會讓人以為沒存到又按一次；畫面在送出前就樂觀更新過了，真的失敗的話 `mutate` 會 toast
並重抓一次。「關閉」留著，那是不存檔離開用的。

到期日欄位點哪裡都會叫出原生日曆（`showPicker()`）。桌機不加這個的話，點欄位只會跳到
年或月那一段數字，日曆得去點右邊那顆小圖示才開得了。舊版 Safari 沒有 `showPicker`，
那邊照原本的行為。

`mutate` 失敗時回 `null`，呼叫端才不會在錯誤訊息後面再蓋一句「已儲存」——
它自己已經 toast 過錯誤了。已儲存／已刪除／已完成三處都改成有回應才報。

## 側欄

圖示原本是 ▦▥▤▤ 這種方塊，七個項目裡有四個長得幾乎一樣，掃過去分不出誰是誰——
等於沒有圖示。改成線稿 svg，形狀講的是那一頁在做什麼：三欄＝看板、月曆＝總覽、
時鐘＝時間表、火花＝AI、卡片＝資料、打勾＝完成、推桿＝設定。描邊用 `currentColor`，
所以選到的時候圖示會跟文字一起變成強調色。

七個項目連成一長條看不出層次，分成「工作」（每天在看的）與「資料」（偶爾才去的）
兩組，各有一個小標題。分組標題是路標不是選項，所以是 `div` 不是 `button`。

沒選到的項目是平的，滑過去才浮起來、選到的才凸起並在左邊亮一條強調色——
都凸就等於都不凸。留白全用 rem，字級 200% 時項目才不會貼到側欄邊緣。

`drag.test.js` 會擋：有項目沒有圖示、兩個項目共用同一個圖示、看得到的項目沒有分組。

## 國定假日

看板總覽的週／月格子會標出台灣的國定假日：那一格抬頭染紅、寫上節日名稱
（只變色的話看不出是什麼節）。格子上面還有一條提醒，**前一段區間就先講下一段的假**——
週檢視講下週、月檢視講下個月，附上日期和星期幾，不然排不了事。假日的意義是
「那幾天做不了事」，等看到已經在那一週就太晚了。

那串日期只能照抄，算不出來：補假、調整放假是行政院人事行政總處每年公告的，
農曆的那幾個又要換算農曆。資料來源是政府行政機關辦公日曆表（取自 TaiwanCalendar
的整理版，不是政府網站直接提供的 API），寫死在 `Code.gs` 的 `HOLIDAYS`。

**每年年底要補下一年**（目前有 2026、2027）。沒補的話畫面會直說
「2028 年的假日還沒更新」，而不是靜靜地當作那年沒有假日——後者會讓人以為
排開的那一週真的可以上班。`HOLIDAY_YEARS` 就是這條警告的依據。

## 看板總覽的週檢視

七天各自是一張卡，不是表格的七個儲存格。一天一個容器，有自己的邊界、抬頭與影子，
比一整片 1px 細線好讀。抬頭是週幾＋日期，右上角標那天幾件事，今天多一圈藍色的環，
過去的日子把抬頭壓暗——一眼看得出這週走到哪。沒事的日子放一個淡淡的破折號。

高度交給同一列最高的那格去撐（grid 本來就會拉齊），只給 7rem 的下限，
不然沒事的日子會空出一大塊。

欄寬下限用 rem（`repeat(auto-fit,minmax(9.5rem,1fr))`），不是寫死七欄：
放大的是字不是視窗，`@media(max-width:…)` 管不到這件事。字級 200% 時七欄
會各剩 65px，一行只放得下一個字；改成 auto-fit 之後它會自己收成兩欄。
月檢視維持固定七欄——那是月曆，欄位要對齊星期。

## 立體感

深色介面要看得出厚度，靠的是三件事一起做，缺一個就會塌回貼紙：

1. **上緣一條亮邊**（`--rim` / `--rim2`，`inset 0 1px 0` 的微白）——光從上面來
2. **往下落的影子**（`--sh1` 卡片 / `--sh2` 面板 / `--sh3` 浮起來的東西）
3. **表面由上而下略暗**（`--face` / `--face2` 的漸層）——同一個平面不會整片同色

層級是固定的：頁面底 → 欄（`--face2`，低一階）→ 卡片（`--face`，高一階）→ 彈出視窗（`--sh3`）。
卡片滑過去浮起 2px、按下去壓回原位，那一下才讓它像可以按的東西而不是一張圖。
拖曳中會關掉浮起（`body.dragging`），不然手指下面的卡片一直跳，瞄不準要放哪一欄。

「＋ 新增任務」那種虛線框刻意留平的——它是還沒有東西的空位，不該跟真的卡片一樣凸起來。

順帶修掉一個同一類的老問題：營運數字五格的 flex 基準寬度本來寫死 `150px`，
字級放到 200% 時五格還是硬擠一排，`$71,325` 被切掉一半。改成 `9.375rem`
就會跟著字一起變寬、擠不下時換行。`drag.test.js` 現在會擋所有寫死 px 的 flex 基準寬度。

## 刪除任務

點卡片的「編輯」，視窗左下有「刪除」，要再確認一次。刪除是把狀態設成「取消」——
任務會從每個頁面消失，但試算表裡那一列留著，翻歷史還找得到。真的想清掉就直接在
試算表刪那一列。

刪除刻意不放在卡片的動作列上，那排按鈕在手機是常駐顯示的，誤按的代價太大。

## 卡片移動

桌機直接把卡片拖到別欄：丟進「AI 正執行工作」＝狀態改進行中，丟進「今日」「明日」＝改到期日；從執行中拖出來會一併退回待辦。

手機三欄是上下堆疊的，垂直拖曳會跟頁面捲動打架，所以那邊改點卡片展開動作列，用「移到今日」「移到明日」按鈕，走的是同一段邏輯。

## 優先級

A 優先處理（直接帶來結果）、B 推進型（讓事情往前走）、C 維護型（不做會出事）。
舊資料的 高/中/低 由 `setup()` 自動換成 A/B/C，寫入時也接受中文。

## API

全部以 JSON 為主，`token` 必帶。POST body 或 GET query 都可以。

| action | 參數 | 說明 |
|---|---|---|
| `ping` | | 測 token |
| `log` | source, project, title, status, summary, link, path, task_id, session_id, prompt, start, end | 新增紀錄；帶 `session_id` 且已存在則更新那一列。`start`／`end` 是給補登用的（`yyyy-MM-dd HH:mm`），不給就用現在 |
| `log_update` | id + title / project / summary / link / status / path | 手改一筆既有紀錄（日曆點時間區塊）；空字串是清掉 |
| `logs` | range=day/week/month, date=yyyy-MM-dd | 讀紀錄 |
| `tasks` | status=open/待辦/進行中/完成 | 讀任務 |
| `task_add` | title, project, due, priority, next, waiting, estimate, note | 新增任務 |
| `task_update` | id + 任一欄位 | 更新任務；status=完成 會填完成時間 |
| `backfill` | 無 | 補齊「任務」表匯入列的 id、建立時間，並正規化優先／狀態／到期日；可重複跑 |
| `board` | date | 看板一次要的全部資料：進行中、今日、明日、未排程、專案池、統計、當日簡報 |
| `projects` | range=day/week/month, date | AI 工作時間表與看板總覽共用：該區間的任務（扁平一份供日曆用、一份依專案分組）、紀錄、未排日期的、國定假日（`holidays`）與下一段區間的假日（`nextHolidays`）|
| `outputs` | source, all=1 | 產出資料庫：帶產出連結的紀錄；`all=1` 才連沒連結的一起列 |
| `pool` | date | AI 專案池：各專案剩什麼、建議順序（附理由）、昨天執行的內容 |
| `done` | range=day/week/month/all, date | 完成項目：完成的紀錄與任務合併，附產出連結與檔案位置 |
| `data` | | 資料區：所有分區與卡片 |
| `metrics` | date（預設今天） | 當天的營運數字，附帶算好的廣告佔比 / 總 ROAS / 流量成本 / 加購成本 |
| `metrics_save` | date + revenue / orders / spend / clicks / carts（至少一個） | 寫當天的數字；只覆蓋帶到的欄位 |
| `sect_save` | name / id + name, color, order | 新增或更新分區；回應直接帶更新後的資料區 |
| `sect_del` | id | 刪分區，裡面的卡片留著（前端歸「未分類」） |
| `item_save` | section, title, body / id + 任一欄位 | 新增或更新卡片 |
| `item_del` | id | 刪卡片 |
| `brief` | date | 今日資料：逾期、今天到期、進行中、接下來、未排程、今日與昨日紀錄、當日簡報文字 |

## Claude Code 自動記錄

**只在自己的電腦上有效。** 跑在 claude.ai 的雲端 session（Claude Code on the web）
連不到 `script.google.com`（代理 403，見下方限制一節），hook 會靜默失敗，那次工作
就不會進看板。要補登以前做的事，用 `log` 帶 `start` 與 `end`（見 API 一節），
時間才會落在真正做事的那一段，而不是「補登的那一刻」。

在你自己的機器上（不是沙盒）：

```bash
mkdir -p ~/.claude/hooks
cp hooks/claude-code-worklog.sh ~/.claude/hooks/ && chmod +x ~/.claude/hooks/claude-code-worklog.sh
cat > ~/.claude/worklog.env <<'EOF'
WORKLOG_URL=https://script.google.com/macros/s/XXXX/exec
WORKLOG_TOKEN=xxxx
EOF
```

把 `hooks/settings.example.json` 的 `hooks` 區塊合併進 `~/.claude/settings.json`。需要 `jq` 和 `curl`，以及連得到 `script.google.com` 的網路（見下方限制一節）。

一個 session 佔一列：SessionStart 建列（進行中）、第一句提示變成標題、每次回覆結束更新為完成並帶最後回覆摘要。

## Cowork 自動記錄

把 `skills/work-log/` 整個資料夾放進 Cowork 的 skills 目錄，並在 `SKILL.md` 裡把 `WORKLOG_URL` 與 `WORKLOG_TOKEN` 換成實際值。它的觸發方式和 `auto-file-organizer` 一樣：每個任務結束時自動參考，送一筆紀錄到看板。

## 沙盒與網路限制

Cowork 的沙盒有兩個限制，決定了兩個 skill 的寫法：

- **家目錄不留存。** `~` 是每次對話重開就清空的暫存區，所以設定不能放 `~/.claude/worklog.env`，改成寫在各自的 `SKILL.md` 裡（skill 檔本身會留存）。
- **代理擋掉 `script.google.com`（403）。** shell 的 `curl` 一定失敗，所以 skill 全部改用瀏覽器開網址呼叫 API：`doGet` 收 query 參數，回應是純 JSON 顯示在頁面上。瀏覽器不受這個限制，實測可通。

副作用是 TOKEN 會出現在網址與瀏覽器紀錄裡。這是個人工具、單人使用，可以接受；不放心就定期到 Apps Script「專案設定 → 指令碼屬性」換掉 `TOKEN`，重跑 `setup`，再更新兩個 skill 和手機。

同一個 403 也套用在 claude.ai 的遠端環境。Claude Code 若跑在你自己的機器上則不受限，hook 用 curl 沒問題；跑在雲端 session 時 hook 會靜默失敗（設計上就是 `exit 0`，不會擋住 Claude Code），那次工作就不會進看板。

## 今日營運數字

看板頂端那條（營業額／廣告花費／廣告佔比／流量／加入購物車）不是看板自己去抓的——
Apps Script 連不到 Shopline 後台和 FB 廣告管理員，兩邊都要登入。數字由 Cowork 的
`skills/daily-metrics/` 抓好，用 `metrics_save` 寫進「指標」工作表，看板只負責讀和換算：

- 廣告佔比＝廣告花費÷營業額（畫面上的那一格）
- 總 ROAS＝營業額÷廣告花費（API 還有回，畫面上不顯示）
- 流量成本＝廣告花費÷連結點擊
- 加購成本＝廣告花費÷加入購物車

**廣告佔比是成本，愈低愈好**，所以好壞的顏色跟其他格子相反：33.3% 以下綠、
66.7% 以上紅。那兩個門檻是從原本 ROAS 那組換算過來的（33.3%＝ROAS 3、
66.7%＝ROAS 1.5），換個講法而已，不是改鬆或改嚴。

**這個佔比會比實際的廣告成本佔比好看。** 分母是 Shopline 全站營業額（含自然流量、
EDM、直接輸入網址的客人），分子只有 FB 廣告花費，所以看起來會比「純廣告帶來的
營收裡有幾成是廣告費」低一截。當趨勢指標很好用，但不要拿去跟 FB 後台的數字對，
那是兩個東西。

**加購成本不能反推轉換率。** FB 的「加入購物車」是歸因轉換（預設 7 天點擊 +
1 天瀏覽），今天報的加購裡有一部分是前幾天點進來的人；點擊則是今天發生的。
兩個數字的基準不同，加購成本看趨勢可以，別當漏斗算比例。

這兩點都寫進了畫面上的 tooltip，標題旁邊有個 ? 記號。

「流量」指的是**廣告的連結點擊**，不是 GA4 的全站工作階段。用付費流量當分母，
流量成本才是「買到一個訪客多少錢」；換成全站流量的話那個數字就沒有意義。

排程建議週一到週日每小時（10:00–21:00），內容「執行 daily-metrics skill」。
同一天重跑會覆蓋當天那一列。還沒抓過的日子，看板會顯示一行提示告訴你怎麼補。

## 早晨簡報

`skills/morning-brief/` 也放進 Cowork 的 skills 目錄，再建一個 Cowork 排程任務：週一到週五 07:30，內容「執行 morning-brief skill」。它會讀任務與昨日紀錄，整理今日清單，寫進「簡報」工作表，手機看板「今日」最上方就會顯示。

另外 claude.ai 上也建了一個同名 Routine（Default 環境，週一至週五 07:30，完成會推播手機）。它要能跑，得先在該環境的網路政策放行 `script.google.com` 與 `script.googleusercontent.com`，並加上 `WORKLOG_URL`、`WORKLOG_TOKEN` 兩個環境變數；未設定前它只會回報環境變數缺漏。兩邊同一天各寫一次簡報時，後寫的覆蓋前面的，不會重複。

## 拖曳

三種東西可以拖，共用同一套 pointer 流程，差別寫在 `DKIND` 裡：

| | 從哪裡拖 | 放到哪裡 | 放下去做什麼 |
|---|---|---|---|
| `t` | 每日看板的卡片 | `.col[data-drop]` | 換欄（開始／今日／明日）|
| `nc` | 資料區的卡片 | `.ncol[data-sect]` | 換分區 |
| `chip` | 看板總覽週格子裡的任務 | `.mc[data-date]` | 改到期日 |

週格子的任務本身是一顆 `<button>`，所以 `press()` 那道「按鈕不處理」的防線要放行它自己，
點擊也改走委派（原本的 `onclick` 會在拖完那一下誤觸發編輯，委派才吃得到 `NODRAG` 保護）。

標題列的 ‹ › 會依目前區間寫成「上一週／下一週」「上一個月／下一個月」——
光是箭頭看不出它會跳多遠。螢幕窄的時候收回只剩箭頭，tooltip 還在。

## blur 裡不要動 DOM

`inline()` 的失焦存檔原本是同步呼叫 `save()` → `paint()`，而 `paint()` 會改 `#view` 的
`innerHTML`。在 blur 事件還在派送的時候抽掉焦點所在的節點，Chrome 會丟
「Failed to set the 'innerHTML' property on 'Element': The node to be removed is no
longer a child of this node」。現在 blur 那條路徑用 `setTimeout(...,0)` 挪到事件之後；
Enter／Esc 是同步的，但 `done` 旗標會擋掉隨後那次 blur，不會存兩次。

## CSS 類別撞名

同一個元素掛兩個類別、兩個類別各自都有「單一裸類別」的規則、又都宣告同一個排版屬性時，
後面那條會無聲蓋掉前面那條。看板已經被咬過兩次：`.now` 同時是日曆的現在時間線和卡片的
今天到期，`.wk` 同時是統計列的週長條圖和看板總覽的週格（`.wk{display:flex}` 把
`.mgrid{display:grid}` 蓋掉，七格擠成一排）。

`drag.test.js` 有一條通用檢查：把真的畫出來的 HTML 掃一遍，任何元素上的兩個類別
只要各自都宣告了 `display` / `position` / `grid-template-columns` / `flex-direction`
其中之一，就讓測試失敗。加新的修飾詞類別之前，先確認那個名字沒被佔走。

## 效能

Apps Script 每讀一次試算表都是一趟慢的 API 呼叫，所以：

- 同一次請求內每張表只讀一次（`CACHE_`）。`board` 原本要讀五次——任務兩次、紀錄三次——現在兩次。
- 寫入後用 `dirty_()` 把那張表的快取丟掉。少了這步，同一次請求裡「寫完再讀」會拿到寫入前的資料。
- 寫入時帶 `board=1`，回應直接附上更新後的看板，前端不用再送第二趟。按一個動作從兩趟網路變一趟。

- 每個頁面的資料在前端各留一份快取，**一分鐘內不再問伺服器**（`FRESH`）。切回剛看過的頁面
  是零請求的；超過一分鐘才重抓，重抓時先畫舊的、不會閃「載入中」，標題列有小圈圈在轉。
- **背景預抓**：目前這頁畫完之後隔一下下，把其他頁默默抓回來放著（一次一頁、中間留空檔，
  不跟前景搶）。使用者在讀這一頁的那幾秒，剩下的頁就都暖好了。
  預抓和真正切頁共用同一組 `vkey()` / `fetchView()`（靠 `asView()` 借用 `VIEW`）——
  另外抄一份的話，哪天 `vkey()` 改了就會存到永遠讀不到的鍵：照樣會動，只是照樣要等，
  而且完全看不出來哪裡壞了。
- 快取的時間戳一定要跟資料一起動，所以三個入口都走 `vset()` / `vclear()` / `vdrop()`。
  漏掉一個就會出現「資料換了但時間戳還很新」，於是一分鐘內都讀到舊的。
- 寫入之後別頁的快取一律作廢（`vdrop`，只留剛從伺服器拿回來的那一頁）——改一件任務，
  專案池、看板總覽、完成項目都會跟著變。作廢完會再排一次背景預抓把它們暖回來。
- 寫入先在本地把畫面改好再送請求，按下去是即時的。伺服器回來的權威資料會覆蓋一次，
  有出入會自動修正；失敗則提示並重新載入。

實測（假伺服器固定延遲 1.5 秒，等同 Apps Script 的一趟）：第一次切到某一頁
從 **1514ms 降到 10ms**，而且是零請求——因為那頁在背景就抓好了。

`test/perf.test.js` 把讀表次數釘住，`test/cache.test.js` 把「切一次頁面要打幾次伺服器」
釘住（看過的一分鐘內零請求、預抓過的零請求、寫入後別頁作廢、沒有時間戳視同過期），
`test/sync.test.js` 確保前端就地算的分欄跟後端一致，改壞了都會被抓到。
