# 從 Notion 把工作項目搬進看板

一次性搬家。搬完 Notion 那個資料庫就可以封存，往後只維護看板一處。
不做雙向同步——技術上做得到（Apps Script 的 `UrlFetchApp` 碰得到 Notion API），
但要存 token、要排程輪詢、還要處理「兩邊同時改同一件事誰贏」，
維護成本只有在「還有別人在 Notion 上看」時才划算。

## 一、從 Notion 匯出

那個資料庫右上角 `⋯` → **Export** → Format 選 **CSV**、Include content 選 **Everything**
（子頁面不用），下載後解壓縮。

## 二、欄位對照

打開「工作看板」試算表的「任務」工作表，欄位順序是固定的：

| 欄 | 名稱 | 從 Notion 的哪一欄來 | 沒有的話 |
|---|---|---|---|
| A | id | 不用填 | 補齊會產生 |
| B | 建立時間 | 不用填 | 補齊會填現在 |
| C | 標題 | Name / 任務名稱 | **必填**，空的那列會被當空列跳過 |
| D | 專案 | Project / 品牌 / 分類 | 留空就是「未分類」 |
| E | 到期日 | Due / 截止日 | 留空＝未排日期 |
| F | 優先 | Priority | 留空當 B |
| G | 狀態 | Status | 留空當待辦 |
| H | 下一步 | 具體要動手的第一件事 | 留空 |
| I | 等待者 | 卡在誰身上 | 留空 |
| J | 預估時數 | | 留空 |
| K | 備註 | 其他想留的欄位都塞這裡 | 留空 |
| L | 完成時間 | 不用填 | |

CSV 的欄位順序跟這裡幾乎一定不一樣。做法：先在另一個分頁貼 CSV，
把需要的欄剪貼成上面的順序，再整塊貼到「任務」工作表**最後一列的下面**
（不要蓋掉現有的資料，也不要貼到第 1 列的表頭）。

## 三、按「補齊匯入的任務」

看板 → 設定 → 從別的工具匯入 → **補齊匯入的任務**（要按兩次，第二次是確認）。

它會做四件事，而且可以重複按，已經正確的不會被改：

1. **補 id 與建立時間。** 貼進來的列沒有 id，看板認不出那張卡片，
   按「開始」「完成」都會失敗。這是一定要跑的原因。
2. **優先級換算成 A/B/C。** High／Urgent／Critical／P0／P1／1 → A；
   Medium／Normal／P2／2 → B；Low／Minor／P3／P4／3 → C。
   認不出來的當 B。
   注意 Critical 是 A 不是 C——比對看的是完整字串，不是第一個字母。
3. **狀態換算。** Not started／Todo／Backlog／Open → 待辦；
   In progress／Doing／WIP → 進行中；Done／Complete／Closed → 完成；
   Cancelled／Archived → 取消。**認不出來的一律當待辦**，
   寧可多做一次，也不要把沒做完的當成完成。
4. **到期日換算成 `yyyy-MM-dd`。** 認得 `2026-09-03`、`2026/9/3`、
   `September 3, 2026`、`Sep 3, 2026`，以及 Notion 的日期區間（取開始那天）。
   `9/3/2026` 這種只有斜線的照美式（月/日）讀，但第一個數字大於 12 時
   只可能是日，會反過來讀。

**看不懂的日期不會亂猜。** 原文搬到「備註」欄前面加「原到期日：」，
到期日清空，執行完的提示會告訴你有幾筆、前三筆長什麼樣，你自己去改。

**已完成的任務不會補「完成時間」。** 我們不知道它當初什麼時候做完的，
不編一個進去。所以匯入的完成任務不會出現在「完成項目」那頁（那頁列的是
實際做出來的東西），但在「看板總覽」還是照到期日排得出來。

## 四、檢查

- 每日看板：逾期的會落在「今日工作」，卡片標「順延 N 天 · 需完成 X/X」
- 看板總覽切「月」：看一下日期有沒有跑掉
- AI 專案池 → 還剩什麼：A/B/C 三塊的件數對不對
- 隨便點一張匯入的卡片，改個標題存檔——存得起來就代表 id 補對了

## 五、收尾

確認沒問題之後，把 Notion 那個資料庫封存（Archive），不要留著兩邊都在改。
往後新任務直接在看板上按「＋ 新增任務」，或叫 Cowork 記。
